Meet Claude

What is Claude?Model family The APICapabilities & limits
1.1 · Definition

A model that turns text into text

Claude is a family of large language models by Anthropic. You send text; it predicts helpful text back — one token at a time. Every request is independent unless you resend the history.

Designed to be helpful, honest, harmless.
Input
"Summarize this email"
↓
Inside the model
Split → predict next token → repeat
No memory of its own · no live internet
↓
Output
"Here are 3 bullet points…"

1.3 · The Claude API

Three roles, one conversation

The Messages API takes a list of messages and returns an assistant reply. Every response reports token usage — the basis for cost.

system = rules · user = request · assistant = reply
# Messages API — the shape system: "You are a support agent…" messages: [ { role: "user", content: "…" }, { role: "assistant", content: "…" }, { role: "user", content: "…" }, ] # response usage: { input_tokens: 812, output_tokens: 143 } # = $
1.4 & 1.5 · Reality check

Know the powers — and the edges

✓Capabilities

  • Understand & generate natural language
  • Summarize · extract · classify · rewrite
  • Write and explain code
  • Read images (vision) & long documents
  • Use tools & return structured output

!Limitations

  • Can hallucinate — confident but wrong
  • Knowledge cutoff — needs tools for fresh facts
  • No memory unless you provide it
  • Finite context window · non-deterministic
  • Cost scales with tokens · needs guardrails

2.6–2.9 · Four power techniques

Steer Claude on purpose

XML Prompting

Tag the parts

<document>…</document> <instructions>…</instructions> <example>…</example>

Few-shot

Show examples

Give 2–3 worked input→output pairs. Teaches format and edge cases faster than prose.

Role Prompting

Assign a persona

"You are a senior tax accountant…" steers tone, vocabulary and rigor.

Prompt Chaining

Split the task

extract → summarize → format. Each step is testable and more reliable than one giant prompt.

Module Three

The model's working memory

TokensContext window OverflowCaching · CALM
3.3 · Tokens

Text is billed in tokens

A token ≈ ¾ of an English word. Both input and output are counted — this is the unit of cost and of limits.

"Claude turns prompts into helpful answers." → 10 tokens
3.1–3.2 · The context window

Everything lives in one window

Context = system prompt + history + docs + tool results + your message. It's finite. Add material and watch it fill toward overflow.

30% usedcontext window limit →
system history documents ⚠ overflow — trim or summarize!
3.6–3.8 · Managing the window

Three ways to keep it CALM

Context Editing

Clear

Drop stale tool results & thinking blocks during long tool-heavy runs.

Compaction

Summarize

Compress earlier history so it still fits. Risk: losing detail.

Memory

Persist

Save facts to files so they survive beyond this session. (→ Module 4)

Overflow = tokens exceed the window → errors or dropped content. Fix by trimming, summarizing, or chunking.
CALM · Cache · exam favourite

The caching prefix rule

Caching matches a stable prefix. Change one byte anywhere in it and everything after is invalidated. Keep volatile data (timestamps, IDs) after the prefix.

✓ cache HIT
[ stable system + tools ] → { today's question }
verify: usage.cache_read_input_tokens > 0 · repeat tokens ≈ 0.1×
✗ cache MISS
[ system + datetime.now() ] → …
a moving value in the prefix silently invalidates every time

5.3–5.5 · Definition & speed

A tool is a schema

Name + description + JSON input schema. The description is how Claude decides when to use it — write it well. Independent tools can run in parallel.

SPIDER: Isolate (least privilege) · Detect (validate every result, watch is_error).
{ "name": "get_weather", "description": "Current weather for a city." ← drives selection, "input_schema": { "type": "object", "properties": { "city": { "type":"string" } }, "required": ["city"] } }
